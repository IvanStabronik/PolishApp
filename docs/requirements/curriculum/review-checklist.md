# Review checklist и операционные locks (Phase 2)

**Статус:** Draft Phase 2 — рабочий QA для автора/внутреннего review; отдельная секция для будущего профессионального методиста JPJO.  
**Baseline:** бриф Phase 2 §10–§11; пакет требований редакции 2.  
**Дата:** 2026-09-05.

Документ **не** заменяет linguistic sign-off. Публикация учебных единиц — только после независимого JPJO (принцип CNT-020 / DEC-016). AI-результаты чеклиста — formative only.

---

## Как пользоваться

1. Автор заполняет **§A** перед передачей вертикали/матрицы.  
2. Внутренний content review отмечает pass/fail/n/a с датой.  
3. Внешний **JPJO** заполняет **§B** (может отклонить при pass по §A).  
4. **§C** — операционные locks: нарушение = блок публикации/маркетинга, даже если педагогика «нравится».

Ответы: `PASS` / `FAIL` / `N/A` / `INTERIM` + комментарий.  
`FAIL` без записанного долга (владелец + срок) запрещает статус уровня «полный».

## B. Чеклист для профессионального методиста JPJO

**Назначение:** независимый sign-off. Reviewer ≠ автор версии единицы/вертикали.  
**Результат вертикали:** `APPROVE` / `APPROVE WITH CONDITIONS` / `REJECT`.  
**AI-отчёт можно приложить, но не может быть основанием APPROVE.**

### B1. Квалификация и независимость

| # | Вопрос | Ожидание |
| --- | --- | --- |
| B1.1 | Подтверждаю компетенцию JPJO / польский FL + методика | Да + краткие credentials |
| B1.2 | Я не автор проверяемой версии | Да (CNT-020) |
| B1.3 | Использовал ли я AI | Если да — только как черновик заметок; решение человеческое |

### B2. Языковая норма

| # | Вопрос | Fail если |
| --- | --- | --- |
| B2.1 | Примеры и ключи соответствуют современной норме PL | Системные ошибки rekcja / вида / mo. / орфографии |
| B2.2 | Контрпримеры корректно помечены | Неправильная форма выглядит как модель |
| B2.3 | Регистр *pan/pani*, wołacz, oficjalna korespondencja уместны | Кальки или детский регистр в институтских жанрах |
| B2.4 | Аудио (если есть) разборчиво для заявленного уровня | Клиппинг/шум/не тот темп (EXM-017) |

### B3. Методика JPJO

| # | Вопрос | Fail если |
| --- | --- | --- |
| B3.1 | Последовательность падежей/аспекта педагогически защитима | Случайный порядок; форма до функции без scaffold |
| B3.2 | Explicit grammar не подменяет коммуникацию и наоборот | Только таблицы или только «поговорите» |
| B3.3 | L1-контрасты точны для заявленного L1 | Один список на три языка; ложные утверждения о UKR/RUS/BEL |
| B3.4 | Exit criteria согласованы с CEFR-дескрипторами и польским стандартом, без подмены | Внутренние % выданы за CEFR; exam readiness смешана с учебным уровнем |
| B3.5 | Покрытие Katalog A/B / list gramatycznych честно | «Полный B1» при дырах в zdrowie/urzęd/gramatyka |

### B4. Экзамен и этика

| # | Вопрос | Fail если |
| --- | --- | --- |
| B4.1 | Нет копий материалов Komisji | Любой OCR/скан/устный zestaw |
| B4.2 | Формулировки не обещают сертификат / сдачу через продукт | EXM-007 |
| B4.3 | Статусы A1/A2 session vs standard отражены верно на дату проверки | Продажа несуществующей сессии |
| B4.4 | Правовая справка B1 (если есть) разделена по процедурам | «B1 для любого ВНЖ» |

### B5. Решение JPJO

```text
Вертикаль / набор единиц: <…>
Дата review: YYYY-MM-DD
Решение: APPROVE | APPROVE WITH CONDITIONS | REJECT
Условия (если есть): <нумерованный список>
Критические дефекты: <…>
Повторный review нужен после: <…>
Подпись / идентификатор reviewer: <…>
```

**REJECT** обязателен при: self-approve; системной ненорме PL; клоне учебника; AI-only оценке high-stakes; ложном exam-claim.

## C. Ops locks (бриф Phase 2 §11)

Зафиксированы как **Assumed (locked for now)** в `11-open-decisions.md`, пока владелец явно не пересмотрит. Curriculum и публикация обязаны соблюдать.

| Lock ID | Решение | Следствие при нарушении |
| --- | --- | --- |
| OPS-01 | **Автор:** основатель с AI-assisted pipeline; AI = черновик, не издатель | Публикация сырого AI-текста запрещена (CNT-010, PED-023) |
| OPS-02 | **Публикация:** только после независимой проверки методистом JPJO | Self-approve запрещён; единица остаётся unpublished (CNT-020). Ops-модель *кто* reviewer — DEC-016 ещё Open, принцип — нет |
| OPS-03 | **AI-feedback:** только formative, явно неофициальный | Нельзя показывать как итоговый exam score / сертификат уровня |
| OPS-04 | **Подтверждённая оценка письма/речи:** человек; отдельная **платная** функция | DEC-002 working lock; AI не единственный судья |
| OPS-05 | **Placement + первый модуль:** бесплатные | DEC-001 working lock |
| OPS-06 | **Полная траектория + exam-mode:** платные | DEC-001; детали UX биллинга — архитектура позже |
| OPS-07 | **Конкретные тарифы:** не определять на этом этапе | Не фиксировать цены в curriculum/маркетинговых обещаниях Phase 2 |

### Дополнительные locks документа 11 (не размывать в Phase 2)

| Lock | Содержание |
| --- | --- |
| UI RUS/UKR/PL | Первая очередь |
| BEL UI | Не обязателен; методика BEL обязательна |
| Серверное хранение голоса | Выключено до privacy/assessment design |
| Возраст | 18+ (DEC-006 assumed) |

### Блокеры публикации (не locks, но стоп-линии)

1. **DEC-016** — кто конкретно обеспечивает независимого JPJO в первые 12 месяцев.  
2. **DEC-007** — GDPR controller при публичном сборе данных/платежей.  
3. **DEC-008 / DEC-013** — имя продукта / юрпроверка правовой справки B1 перед маркетингом.

## D. Мини-чеклист перед статусом «полный уровень»

Отметить все пункты:

- [ ] Level matrix Phase 2 утверждена (не stub)  
- [ ] Exit criteria уровня заполнены; CEFR vs internal vs exam разведены  
- [ ] Coverage Katalog A/B + grammar: нет gap без долга  
- [ ] §A без критических FAIL  
- [ ] §B = APPROVE или APPROVE WITH CONDITIONS (условия закрыты)  
- [ ] Ops locks OPS-01…07 соблюдены  
- [ ] `standard_status` / `session_availability` обновлены, дата проверки актуальна  
- [ ] Дисклеймер «не государственный сертификат» на пользовательских экранах уровня  

Любой пропуск → статус максимум `interim`.
