# 08. Нефункциональные требования

Этот документ задаёт ограничения качества и эксплуатации. Он **не** выбирает стек, облако и схему данных. Где ограничение влияет на будущую архитектуру, это сказано прямо.

Числовые пороги без внешнего стандарта помечены `ASSUMPTION`.

---

### NFR-001 — Responsive web как единственный клиент первой очереди

- **Формулировка:** Целевой клиент — web в современном браузере на телефоне и десктопе. Нативное приложение не требуется для целевого состояния A1–B2.
- **Причина:** Бюджет и 15 часов; P-OLENA всё равно в браузере.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Критический путь `FUN-230` проходит в актуальных стабильных Chrome, Firefox, Edge, Safari (последние две major-версии — `ASSUMPTION`).
- **Зависимости:** FUN-230, NFR-010
- **Риски:** «Сначала приложение».
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** manual test

### NFR-002 — Время отклика учебного шага

- **Формулировка:** Показ следующего закрытого пункта и результат проверки ключа отображаются не позднее 2 секунд p95 при обычной нагрузке первой аудитории, без вызова генеративной модели.
- **Причина:** Послесменная усталость; 8 секунд на галочку убивают сессию.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Измерение p95 на сценарии «ответил → увидел ключ»; регресс >2с — дефект.
- **Зависимости:** FUN-062, NFR-004
- **Риски:** Синхронный LLM в этом шаге.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION` 2с / p95
- **Проверка:** automated test, manual test

### NFR-003 — Доступность сервиса

- **Формулировка:** Учебный контур целевого состояния проектируется так, чтобы плановые окна обслуживания были объявлены заранее. Количественный SLA не утверждается до появления бюджета (`DEC-001`).
- **Причина:** Не выдумывать 99.9% без денег на него.
- **Основная персона:** P-ADMIN
- **Приоритет:** Advanced
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Есть статус/баннер планового окна; нет скрытого требования «всегда up» в Critical до решения о бюджете.
- **Зависимости:** DEC-001
- **Риски:** Обещание enterprise-SLA команде из одного человека.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** manual test

### NFR-004 — Ограничение расходов на генеративный AI

- **Формулировка:** Базовый учебный путь (теория, закрытые упражнения, прогресс, ключ, утверждённые объяснения) выполняется **без обязательных** вызовов внешней генеративной модели. Любые AI-вспомогательные функции ограничены по стоимости/квоте и могут быть полностью отключены без поломки базового пути. Конкретный механизм (флаг, конфиг, circuit breaker) выбирается на этапе архитектуры.
- **Причина:** BUS-006.
- **Основная персона:** P-ADMIN
- **Приоритет:** Critical
- **Target necessity:** Mandatory
- **Delivery stage:** V0
- **Критерии приёмки:** При отключённых AI-функциях базовый путь проходит e2e; превышение квоты деградирует к утверждённому банку, а не к открытому счёту.
- **Зависимости:** FUN-066, BUS-006, PRN-010
- **Риски:** Тихий per-item completion.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test, manual test

### NFR-005 — Эксплуатация малой командой

- **Формулировка:** Штатная эксплуатация контента рассчитана на основателя ≤15 ч/нед плюс независимый профессиональный методист/reviewer (операционная модель — `DEC-016`). Если человеческая оценка письма/речи включена и очередь превышает согласованный SLA (рабочее допущение 72 ч), система показывает честный `pending`, а не молчаливый AI-pass.
- **Причина:** Иначе продуктивные навыки лгут.
- **Основная персона:** P-ADMIN
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V0
- **Критерии приёмки:**
  1. Наблюдаемо: есть список работ awaiting human review с возрастом заявки **или** productive high-stakes оценка отключена.
  2. Нет скрытого автозачёта при переполнении.
  3. Qualitative ops criterion: в runbook описано, кто reviewer и что делать при отсутствии reviewer >7 дней (стоп публикации).
- **Зависимости:** ASM-010, DEC-002, DEC-016
- **Риски:** Обещать мгновенную проверку эссе одному человеку.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` (`ASSUMPTION` 72 ч)
- **Проверка:** manual test

### NFR-006 — Восстановление после потери данных

- **Формулировка:** Учебные свидетельства, контент published-версий и данные учёток подлежат резервному копированию. Конкретная технология не задаётся. Должна существовать проверяемая процедура восстановления published-контента и учётных записей.
- **Причина:** Контент — актив; потеря ключей убивает продукт.
- **Основная персона:** P-ADMIN
- **Приоритет:** Critical
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Документированная процедура restore есть до публичного запуска первой вертикали; тестовое восстановление на копии выполнено хотя бы раз.
- **Зависимости:** CNT-006
- **Риски:** Единственная копия на ноутбуке основателя. Ограничение для архитектуры: единственная рабочая копия контента недопустима.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** manual test

### NFR-007 — Наблюдаемость учебного контура

- **Формулировка:** Оператор видит ошибки проверки ключей, сбои загрузки аудио, сбои записи речи и отказы публикации. Логи не содержат полных голосовых файлов и паролей.
- **Причина:** Иначе 15 часов уходят на «у меня не нажимается».
- **Основная персона:** P-ADMIN
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Инцидент «аудио не играет» воспроизводим по идентификатору сессии/запроса (конкретный формат — архитектура) без скачивания чужого голоса из лога.
- **Зависимости:** SEC-005, FUN-180
- **Риски:** Логи-свалка PII.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** manual test

### NFR-008 — Аудируемость контента

- **Формулировка:** Для любой published-единицы можно ответить: кто автор, кто reviewer, какая версия, какие источники, когда проверка.
- **Причина:** CNT provenance.
- **Основная персона:** P-REVIEWER
- **Приоритет:** Critical
- **Target necessity:** Mandatory
- **Delivery stage:** V0
- **Критерии приёмки:** Запрос по id единицы возвращает поля `CNT-002`–`CNT-008`.
- **Зависимости:** FUN-174
- **Риски:** «Это всегда так было».
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test

### NFR-009 — Разборчивость учебного аудио

- **Формулировка:** Оцениваемый listening A1 должен быть разборчив на встроенной динамике телефона в тихой комнате (качественная субъективная приёмка reviewer + выборочный user research). Технические минимумы кодека/битрейта не фиксируются до выбора стека, но запись с клиппингом и шумом кафе не публикуется на A1 как единственный стимул.
- **Причина:** Стандарт A1 требует почти идеальных условий.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:**
  1. Qualitative listening review: методист выставляет pass/fail по рубрике (клиппинг / фоновый шум / разборчивость слов уровня) для 100% новых assessed listening A1-стандарта в релизе.
  2. Fail блокирует публикацию записи.
  3. Допускается выборочный user research (≥3 учащихся) как доп. сигнал, не как единственный критерий.
- **Зависимости:** EXM-017, FUN-110
- **Риски:** «Аутентичный шум трамвая» на A1-стандарте.
- **Статус:** Proposed
- **Источник:** załącznik nr 1 A1 listening
- **Проверка:** linguistic review, user research

### NFR-010 — Браузеры и запись речи

- **Формулировка:** Запись речи требует явного разрешения микрофона. Если браузер не умеет записать, задание показывает понятный отказ и альтернативу (отложить / текстовый черновик ответа, если методически допустимо), а не пустой экран.
- **Причина:** Safari / корпоративные телефоны.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Отказ микрофона не ломает остальной урок.
- **Зависимости:** FUN-130, ACC-006
- **Риски:** Весь урок заблокирован из-за микрофона.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** manual test

### NFR-011 — Масштаб первой аудитории

- **Формулировка:** Количественная ёмкость (тысячи одновременных) не утверждается: аудитория неизвестна. Система не должна требовать многолюдной эксплуатации, чтобы обслужить первую сотню учащихся.
- **Причина:** Не проектировать гиперскейл.
- **Основная персона:** P-ADMIN
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V0
- **Критерии приёмки:**
  1. В пакете требований нет скрытого Mandatory «нужен выделенный кластер / постоянная большая команда».
  2. Qualitative architecture review criterion (на этапе архитектуры): предложение, требующее постоянной команды >2 FTE только для базового пути V1, отклоняется как несовместимое с BUS-006, пока владелец явно не утвердит иное.
- **Зависимости:** BUS-006
- **Риски:** Overengineering.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** content review (на этапе архитектуры)

### NFR-012 — Online-first

- **Формулировка:** Офлайн-режим не входит в целевое состояние первой очереди. Прерванная сессия должна уметь продолжить после восстановления сети без потери уже сохранённых ответов.
- **Причина:** Не плодить ложное обещание метро без сети.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Потеря сети показывает состояние; повторная отправка не дублирует свидетельство с тем же attempt id.
- **Зависимости:** FUN-081, DEC-010
- **Риски:** Двойной счёт ошибок.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** manual test, automated test

### NFR-013 — Детерминированная проверка закрытых пунктов

- **Формулировка:** Один и тот же ответ на одну версию пункта всегда даёт тот же результат проверки, независимо от времени суток и нагрузки.
- **Причина:** Падеж не может «иногда быть верным».
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Идемпотентные фикстуры ключей в автотестах.
- **Зависимости:** FUN-060, ASM-006
- **Риски:** Нестабильный нормализатор ввода.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test

### NFR-014 — Время до первой пользы

- **Формулировка:** Новый учащийся может начать placement не позднее чем через 10 минут после открытия сайта, если почта подтверждается в этом окне. Если подтверждение почты задерживается, доступен ограниченный гостевой просмотр одного публичного объяснения концепта без записи прогресса — `ASSUMPTION`.
- **Причина:** P-OLENA бросит длинную воронку.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Измеренный сценарий ≤10 минут до первого placement-пункта при успешном подтверждении.
- **Зависимости:** FUN-001, FUN-020
- **Риски:** Онбординг на 20 экранов.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION` 10 минут
- **Проверка:** user research, manual test

### NFR-015 — Предсказуемая стоимость медиа

- **Формулировка:** Хранение аудио учащихся и учебных записей не должно быть безлимитным без политики срока (`SEC-006`). Учебные записи (контент) хранятся, пока единица published/archived; голос учащегося — по сроку.
- **Причина:** Голос дороже текста и опаснее.
- **Основная персона:** P-ADMIN
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Политика срока существует до включения `FUN-130` в прод.
- **Зависимости:** SEC-006, DEC-005
- **Риски:** Вечные записи «на всякий случай».
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** manual test
