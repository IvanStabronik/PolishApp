### Проверка целостности curriculum

```bash
python scripts/validate-curriculum.py
```

Скрипт (только stdlib) проверяет уникальность ID, prerequisites, циклы, счётчики, покрытие FN, LEX/ERR ссылки, запрет временных псевдо-ID. Код выхода `0` = OK. Отчёт: [curriculum/phase-2-integrity-report.md](curriculum/phase-2-integrity-report.md).

Этот каталог задаёт проверяемую систему требований. Он не выбирает стек, не проектирует базу, не описывает API и не содержит UI-макетов.

## 2. Найденные ограничения и противоречия

### Ограничения, зафиксированные из брифа

- Основатель доступен около 15 часов в неделю и опирается на Cursor / AI-инструменты.
- Бюджет не определён. Система не должна требовать неограниченных расходов на AI API или постоянную большую команду.
- Целевая спецификация — полноценная A1–B2-платформа, а не toy MVP. Сокращать целевое состояние нельзя.
- Поставка идёт законченными вертикальными этапами. Целевое состояние ≠ первый релиз.
- Контент должен быть оригинальным. Учебники можно сравнивать, нельзя клонировать.
- Первая аудитория — не «все иностранцы», а взрослые носители украинского, русского и белорусского, уже живущие в Польше.
- Требования без польской специфики запрещены.

### Ограничения, найденные во внешних источниках

- Государственный экзамен регулируется [Rozporządzenie Ministra Nauki i Szkolnictwa Wyższego z dnia 14 lutego 2025 r.](https://dziennikustaw.gov.pl/D2025000021701.pdf) (Dz.U. 2025 poz. 217) на основании [ustawy o języku polskim](https://certyfikatpolski.pl/).
- Платформа **не является** субъектом, уполномоченным проводить государственный экзамен, и **не выдаёт** государственный сертификат.
- Официальные экзаменационные наборы копировать нельзя; лицензия на прошлые бумаги не предполагается.
- Юридические применения сертификата B1 различны: для **obywatelstwo** и **pobyt rezydenta długoterminowego UE** B1 фигурирует в законе; для обычного **pobyt stały** (art. 195) это не общий формальный порог. Продукт не должен смешивать эти процедуры.

## 4. Схема требования

Каждое атомарное требование содержит все поля ниже. Формулировки вида «удобный интерфейс», «качественный AI», «эффективное обучение» без измеримого определения запрещены.

| Поле | Назначение |
| --- | --- |
| ID | Стабильный идентификатор |
| Формулировка | Одно проверяемое утверждение |
| Причина | Зачем это нужно именно этой платформе / польскому |
| Основная персона | Кто получает ценность |
| **Target necessity** | Mandatory / Important / Optional — нужна ли в целевом состоянии |
| **Delivery stage** | V0…V5 / Later — когда поставляется |
| Приоритет | Critical / Core / Advanced / Later — **риск/критичность**, не «важность вообще». Critical только если без требования: нарушение закона/безопасности, непроверенный контент, ложный уровень/сертификат, потеря данных, утрата системности польского A1–B2 |
| Критерии приёмки | Наблюдаемые условия готовности (или qualitative review с рубрикой) |
| Зависимости | Другие ID или внешние условия |
| Риски | Что ломается, если требование ослабить |
| Статус | Proposed / Approved / Implemented / Verified |
| Источник | Официальный источник / бриф (только прямые решения) / `ASSUMPTION` / `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION` |
| Способ проверки | automated test / manual test / content review / linguistic review / user research |

Полный индекс necessity/stage: [14-priority-stage-index.md](14-priority-stage-index.md).

`PRN-xxx` — принципы, не пользовательские истории. Они режут решения, но сами по себе не поставляются.

### Приоритеты

| Приоритет | Значение |
| --- | --- |
| **Critical** | Без этого целевое состояние продукта ложно или незаконно / неэтично |
| **Core** | Нужно для полноценной A1–B2-платформы первой аудитории |
| **Advanced** | Нужно для зрелости, не блокирует определение целевого продукта |
| **Later** | Поздние аудитории или отложенные режимы |

Приоритет описывает **целевое состояние**, не спринт. Порядок реализации задаёт документ 10.

### Способы проверки

- **automated test** — детерминированное поведение системы.
- **manual test** — сценарий проверяющего.
- **content review** — методическая проверка оригинальности, покрытия, ключей.
- **linguistic review** — проверка польского и L1-комментариев носителем / методистом.
- **user research** — наблюдение или интервью с целевой персоной.

## 5. Глоссарий

| Термин | Значение в этом пакете |
| --- | --- |
| **Концепт** | Атомарная единица освоения: одно польское явление с границами применения, например «dopełniacz po liczbach 5+», а не «падежи» целиком |
| **Урок** | Методически собранный набор концептов, примеров и упражнений на одну учебную цель |
| **Траектория** | Упорядоченный граф концептов A1–B2 с пререквизитами и спиральным возвратом |
| **Mastery** | Измеримое состояние концепта, а не факт открытия урока |
| **L1-методика** | Отдельные объяснения, контрасты, банки ошибок и порядок подачи для конкретного первого языка |
| **Рецептивные навыки** | Чтение и аудирование |
| **Продуктивные навыки** | Письмо и говорение |
| **Закрытый пункт** | Задание с однозначным ключом |
| **Продуктивное задание** | Письмо или речь, требующие рубрики |
| **Госэкзамен** | Państwowy egzamin certyfikatowy z języka polskiego jako obcego |
| **Вертикаль** | Законченный поставленный срез: контент + упражнения + оценка + публикация для ограниченного уровня/навыка |
| **Provenance** | Происхождение единицы контента: автор, источники, версия, проверка |

## 6. Правила для следующих этапов

Следующие этапы (архитектура, Figma, implementation tasks) **не начинаются** из этого пакета автоматически. Они могут начаться только после утверждения владельцем продукта или явного поручения.

Если требование влияет на архитектуру, оно зафиксировано как ограничение, без предложения реализации.
