# 06. Требования к оценке (assessment)

Оценка в продукте служит трём целям: поставить учащегося на карту концептов, вести обучение и зафиксировать внутренний порог уровня. Она **не** выдаёт государственный сертификат.

---

### ASM-001 — Диагностическая оценка

- **Формулировка:** Диагностика измеряет владение концептами и навыками, а не удовлетворённость или время в приложении. Результат — профиль пробелов.
- **Причина:** USR-001, P-VIKTOR.
- **Основная персона:** P-VIKTOR
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Отчёт содержит концепты со статусами; есть пункты интерференции; нет единственного vanity-балла как главного вывода.
- **Зависимости:** FUN-020, PED-013
- **Риски:** 15 общих CEFR-вопросов.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** content review, user research

### ASM-002 — Формирующая оценка

- **Формулировка:** В учебном режиме оценка немедленно учит: ключ, концепт, код ошибки. Она пишет свидетельства с флагом `formative` и `hinted` при подсказке.
- **Причина:** Польская форма чинится в момент ошибки.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Соответствует `FUN-062`; formative не использует порог «сдал уровень».
- **Зависимости:** FUN-062, FUN-150
- **Риски:** Учебный квиз как экзамен без обратной связи.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** manual test

### ASM-003 — Итоговая оценка уровня

- **Формулировка:** Суммативный тест уровня принимает решение «внутренний порог уровня достигнут / не достигнут» по заранее опубликованным правилам продукта. Правила не копируют § 23 молча: если они совпадают с exam-mode, это явно подписано «как на госэкзамене, но это не он».
- **Причина:** Нужен внутренний критерий завершения вертикали.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Правила порога видны до старта; дисклеймер обязателен.
- **Зависимости:** FUN-152, EXM-007
- **Риски:** Скрытый порог.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** manual test, content review

### ASM-004 — Конструкт placement

- **Формулировка:** Placement обязан зондировать минимум: (1) падеж после предлога, (2) аспект или его отсутствие, (3) согласование, (4) одну орфографическую пару, (5) чтение короткого бытового текста, (6) слух короткой реплики, (7) ≥3 L1-ловушки выбранного языка, если L1 уже указан. Письмо/речь — по `DEC-002`.
- **Причина:** Иначе placement снова станет лексическим IQ-тестом.
- **Основная персона:** P-VIKTOR
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Спецификация placement перечисляет эти конструкты; ревью отклоняет вариант без (1)–(7).
- **Зависимости:** FUN-020, PED-013, DEC-009
- **Риски:** Самооценка + 5 фраз.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** content review

### ASM-005 — Правила mastery (рабочее допущение)

- **Формулировка:** Пока `DEC-003` не утверждён, действуют правила: `gotowy` — ≥5 неспровоцированных (`hinted=false`) верных закрытых свидетельств ≥2 типов за 21 день и доля верных ≥75% за это окно; `mastered` — `gotowy` плюс ≥8 свидетельств ≥3 типов, доля ≥80%, и если концепт `productive` — ≥1 квалифицированное продуктивное свидетельство; ошибка в `mastered` снижает до `gotowy`; нет свидетельств N дней — `decaying` (N=28 по умолчанию).
- **Причина:** Нужна проверяемая формула, не «система умная».
- **Основная персона:** P-DARIA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Правила опубликованы в продукте для учащегося простым языком; автотесты фиксируют переходы состояний на фикстурах.
- **Зависимости:** FUN-080, FUN-082, FUN-083, DEC-003
- **Риски:** Слишком мягкий порог = ложный B1; слишком жёсткий = отток.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** automated test, user research

### ASM-006 — Надёжность закрытых пунктов

- **Формулировка:** Закрытый пункт имеет однозначный ключ либо явный список допустимых ключей (регистр, необязательная пунктуация). Неоднозначный пункт снимается с публикации.
- **Причина:** Польская орфография и варианты (*w Polsce / w RP*) иначе дают ложные ошибки.
- **Основная персона:** P-AUTHOR
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Review отклоняет пункт с двумя разумными ответами без обоих в ключе.
- **Зависимости:** CNT-013, FUN-175
- **Риски:** «Правильно только как в голове автора».
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** linguistic review, content review

### ASM-007 — Содержательная валидность для польского

- **Формулировка:** Спецификация теста обязана назвать польский конструкт (падеж, вид, модуль экзамена). Тест «общий язык» без конструкта не публикуется как уровневый.
- **Причина:** PRN-001.
- **Основная персона:** P-AUTHOR
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** У суммативного и exam-теста есть таблица спецификации конструктов.
- **Зависимости:** PED-027, EXM-014
- **Риски:** Случайная пачка пунктов.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** content review

### ASM-008 — Ключи и коды

- **Формулировка:** Каждый закрытый пункт связан с ключом и хотя бы одним концептом. Дистракторы по возможности несут код ошибки.
- **Причина:** Без кода нет L1-объяснения.
- **Основная персона:** P-AUTHOR
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Публикация без concept id невозможна.
- **Зависимости:** FUN-064, CNT-013
- **Риски:** «Просто неправильно».
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test

### ASM-009 — Человеческая рубрика письма и речи

- **Формулировка:** Продуктивные задания для exam-mode и для `mastered` продуктивного концепта оцениваются по письменной рубрике человеком. Рубрика включает: выполнение жанра, лексика уровня, грамматические столпы задания, орфография, регистр. Балл за «беглость впечатления» без критериев запрещён.
- **Причина:** Польский регистр и падеж в письме не сводятся к длине текста.
- **Основная персона:** P-REVIEWER
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V4
- **Критерии приёмки:** Рубрика опубликована до сдачи; оценщик заполняет критерии, не одно число.
- **Зависимости:** FUN-122, FUN-132, DEC-002
- **Риски:** «Ставлю 7/10 на глаз».
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` (практика exam speaking/writing)
- **Проверка:** linguistic review, manual test

### ASM-010 — Запрет AI-only на высоких ставках

- **Формулировка:** Генеративная модель не выставляет единолично: результат exam-mode по письму/речи; переход продуктивного концепта в `mastered`; внутренний «сдан уровень» если он опирается на продуктивный модуль.
- **Причина:** BUS-010, PED-023. Модель ненадёжный судья польской нормы.
- **Основная персона:** P-REVIEWER
- **Приоритет:** Critical
- **Target necessity:** Mandatory
- **Delivery stage:** V0
- **Критерии приёмки:** Нет программного пути авто-pass указанных решений; автоподсветка, если есть, отделена от балла.
- **Зависимости:** FUN-122, FUN-132, BUS-010
- **Риски:** Маркетинг «AI examiner».
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test, manual test

### ASM-011 — Запрет скрытого standard setting

- **Формулировка:** Пороги внутренних тестов фиксируются до публикации теста и не подгоняются после просмотра результатов первой когорты без новой версии теста и записи причины.
- **Причина:** Иначе порог «подкрутят», чтобы все сдали.
- **Основная персона:** P-ADMIN
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Смена порога создаёт новую версию теста (`CNT-006`) и пишет audit.
- **Зависимости:** FUN-172, FUN-193
- **Риски:** Политический pass-rate.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** automated test

### ASM-012 — Анализ пунктов

- **Формулировка:** Для пунктов с ≥30 ответами автор видит долю верных и частоту дистракторов. Пункт с долей верных <20% или >98% при достаточном N помечается к пересмотру (не автоудаляется).
- **Причина:** Плохой ключ или двусмысленность в польском часто маскируются под «трудный падеж».
- **Основная персона:** P-AUTHOR
- **Приоритет:** Advanced
- **Target necessity:** Optional
- **Delivery stage:** Later
- **Критерии приёмки:** Отчёт доступен в кабинете автора; пороги 20/98 и N=30 — рабочие допущения.
- **Зависимости:** FUN-180
- **Риски:** Автоудаление живого трудного liczebniki.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** manual test

### ASM-013 — Справедливость между L1

- **Формулировка:** Пункт не должен требовать знания украинского/русского/белорусского как условия правильного польского ответа. L1 помогает в объяснении, не в ключе.
- **Причина:** Смешанные пары, разные L1 в одной семье.
- **Основная персона:** P-NATALLIA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Review отклоняет пункт, ключ которого — перевод на L1, а не польская форма, кроме явных XT-32/XT-52.
- **Зависимости:** CNT-017
- **Риски:** Тест на русский, а не на польский.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** linguistic review

### ASM-014 — Лимит времени в exam-mode

- **Формулировка:** Exam-mode ограничивает время модуля. Лимиты не могут превышать официальные потолки постановления для данного уровня и не выдаются за официальные, если они короче. Фактические минуты модуля — контент-параметр с датой сверки.
- **Причина:** § 14 задаёт потолки всей письменной части, не минуты каждого модуля; точные минуты на бланке определяет Komisja.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V4
- **Критерии приёмки:** Таймер виден; истечение закрывает модуль; в справке указано: «официальные минуты модуля задаёт бланк сессии; наши — тренировочные, сверены с публичными описаниями центров, дата сверки X».
- **Зависимости:** EXM-001, CNT-008
- **Риски:** Выдать 25 минут слуха B1 как закон.
- **Статус:** Proposed
- **Источник:** Dz.U. 2025 poz. 217 § 14; минуты модулей — публичные описания центров, не текст закона → сверка обязательна
- **Проверка:** manual test, content review

### ASM-015 — Два режима обратной связи

- **Формулировка:** Учебный режим показывает ключ сразу. Проверочный (промежуточный, суммативный, exam-модуль) скрывает ключ до конца попытки/модуля.
- **Причина:** Иначе exam-mode бессмысленен.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Переключение режима тестируется автотестами; случайный hint в exam-mode — дефект.
- **Зависимости:** FUN-062, FUN-151, FUN-160
- **Риски:** Утечка ключа.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test

### ASM-016 — Пересдачи

- **Формулировка:** Суммативный тест уровня и exam-mode можно пересдать не раньше чем через 7 дней, если не действует иное опубликованное правило версии теста. Формирующие тесты без лимита, но банк должен менять пункты (`FUN-061`).
- **Причина:** Натаскивание на тот же бланк.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Лимит 7 дней соблюдён; вторая попытка по возможности другая сборка банка.
- **Зависимости:** FUN-022, FUN-061
- **Риски:** Десять попыток за вечер = «сдал».
- **Статус:** Proposed
- **Источник:** `ASSUMPTION` 7 дней
- **Проверка:** automated test
