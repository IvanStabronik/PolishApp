# 03. Функциональные требования

Требования описывают поведение системы в целевом состоянии. Они не предписывают фреймворк, схему БД или API.

Общий шаблон полей — в [README.md](README.md). Если требование влияет на архитектуру, фиксируется **ограничение**, не решение.

---

## 3.1 Регистрация и профиль

### FUN-001 — Регистрация взрослого учащегося

- **Формулировка:** Человек может создать учётную запись учащегося, указав адрес электронной почты, пароль или иной утверждённый способ входа, подтвердив возраст 18+ и обязательные согласия.
- **Причина:** Первая аудитория — взрослые; детская экзаменационная группа вне scope.
- **Основная персона:** P-OLENA
- **Приоритет:** Critical
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:**
  1. Без подтверждения 18+ учётная запись учащегося не создаётся.
  2. Без обязательных согласий `SEC-002` регистрация не завершается.
  3. Повтор той же почты не создаёт вторую активную учётку.
- **Зависимости:** SEC-002, SEC-009, DEC-006
- **Риски:** Неявный доступ несовершеннолетних.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` (`ASSUMPTION` e-mail как первый фактор)
- **Проверка:** automated test, manual test

### FUN-002 — Вход и восстановление доступа

- **Формулировка:** Зарегистрированный пользователь входит и может восстановить доступ к учётной записи без обращения к администратору в штатном случае.
- **Причина:** Иначе 15 часов основателя уйдут на пароли.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Неверный пароль не раскрывает, существует ли почта, сверх общего сообщения; восстановление требует владения фактором входа.
- **Зависимости:** FUN-001, SEC-004
- **Риски:** Перечисление аккаунтов.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** automated test

### FUN-003 — Роли в одной системе

- **Формулировка:** Система различает роли learner, author, reviewer, admin. Одна персона может иметь несколько ролей, но self-approve контента запрещён.
- **Причина:** Авторский контур и учебный контур нельзя смешивать в одной «админке без правил».
- **Основная персона:** P-ADMIN
- **Приоритет:** Critical
- **Target necessity:** Mandatory
- **Delivery stage:** V0
- **Критерии приёмки:** Учащийся не видит черновики; reviewer не может утвердить единицу, где он автор текущей версии.
- **Зависимости:** USR-015, CNT-020, FUN-175
- **Риски:** Основатель в одной роли обходит review.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test

## 3.2 L1 и цели

### FUN-010 — Обязательное определение L1

- **Формулировка:** До построения персональной траектории учащийся выбирает L1 из списка, где украинский, русский и белорусский доступны как отдельные значения; значение «славянский» отсутствует.
- **Причина:** PRN-004.
- **Основная персона:** P-NATALLIA
- **Приоритет:** Critical
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Траектория не стартует без L1; смена L1 пересчитывает L1-заметки и не стирает mastery концептов.
- **Зависимости:** USR-002, PED-014
- **Риски:** Дефолт «русский» для всех с кириллицей.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test, manual test

### FUN-011 — Цели обучения

- **Формулировка:** Учащийся выбирает ≥1 цель: повседневная жизнь в Польше; работа; семья и школа; интеграция; госэкзамен A1/A2/B1/B2; выход на B1 как порог самостоятельности.
- **Причина:** Жанры письма и регистр зависят от цели.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Цель сохраняется в профиле и используется рекомендателем `FUN-033`; цель «экзамен» открывает exam-mode соответствующего уровня, если контент опубликован.
- **Зависимости:** USR-003, FUN-033, FUN-160
- **Риски:** Цель не влияет на очередь занятий.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** manual test

### FUN-012 — Учебный бюджет времени

- **Формулировка:** Учащийся указывает доступные минуты в неделю из закрытого набора (например 60 / 120 / 210 / 360). Рекомендатель не планирует сессию длиннее указанного дневного куска.
- **Причина:** P-OLENA занимается после смены; перегруз срывает привычку.
- **Основная персона:** P-OLENA
- **Приоритет:** Advanced
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Рекомендованная сессия ≤ выбранного дневного лимита ±10%; лимит можно изменить.
- **Зависимости:** FUN-033
- **Риски:** «Час грамматики» в профиле «20 минут».
- **Статус:** Proposed
- **Источник:** `ASSUMPTION` о наборе корзин времени
- **Проверка:** automated test

### FUN-013 — Предшествующий опыт

- **Формулировка:** Учащийся может указать самооценку и контекст: «не учил», «учил по учебнику», «говорю на работе», «жил N лет». Placement остаётся обязательным; самооценка не заменяет его.
- **Причина:** P-VIKTOR завышает уровень; системе нужно знать, что ждать ложной беглости.
- **Основная персона:** P-VIKTOR
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Флаг «бытовой польский есть» включает в placement ловушки интерференции; самооценка не записывает CEFR в mastery.
- **Зависимости:** FUN-020, ASM-004
- **Риски:** Пропуск placement по самооценке B1.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` (`ASSUMPTION`)
- **Проверка:** manual test

## 3.3 Placement test

### FUN-020 — Диагностический placement

- **Формулировка:** Новый учащийся проходит placement, который зондирует концепты A1–B1 (и B2, если заявлен опыт) по грамматике, лексике, чтению и слуху; письмо и речь в placement могут быть короткими или отложены, но не подменяются «угадай уровень».
- **Причина:** Нужна карта систем, не один балл.
- **Основная персона:** P-VIKTOR
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:**
  1. Результат — набор статусов концептов + рекомендуемая точка входа.
  2. Есть пункты-ловушки восточнославянской интерференции.
  3. Можно прервать и продолжить без потери ответов.
- **Зависимости:** ASM-001, ASM-004, PED-013, DEC-009
- **Риски:** 10 вопросов «как дела» = ложный B1.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** content review, user research, manual test

### FUN-021 — Placement не выдаёт сертификат уровня

- **Формулировка:** Результат placement помечен как внутренняя диагностика. Система не называет его государственным уровнем и не обещает соответствие порогу § 23.
- **Причина:** PRN-009.
- **Основная персона:** P-OLENA
- **Приоритет:** Critical
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** На экране результата есть дисклеймер; нет кнопки «скачать сертификат A2».
- **Зависимости:** EXM-007
- **Риски:** Скриншот как «документ для воеводы».
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** manual test

### FUN-022 — Повторная диагностика

- **Формулировка:** Учащийся может запустить новую диагностику не чаще чем раз в 14 дней либо после суммативного теста уровня. Новая диагностика не стирает историю, а добавляет свидетельства.
- **Причина:** Частый перезапуск — способ «накликать» уровень.
- **Основная персона:** P-VIKTOR
- **Приоритет:** Advanced
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Лимит 14 дней соблюдён; история попыток доступна учащемуся.
- **Зависимости:** FUN-020, ASM-016
- **Риски:** Сброс mastery ради эго.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION` интервала 14 дней
- **Проверка:** automated test

## 3.4 Траектория A1–B2

### FUN-030 — Учебная траектория и связи пререквизитов

- **Формулировка:** Система хранит и показывает траекторию учебных единиц A1–B2 с пререквизитами, уровнем CEFR, навыками и тегами польских систем. Конкретная реализация (граф, таблица связей, иное) — этап архитектуры; требуется объяснимый порядок и зависимости, не конкретная технология graph DB.
- **Причина:** Спираль должна быть видна.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** У каждой учебной единицы есть ID, уровень, пререквизиты (если есть), навык(и), статус публикации.
- **Зависимости:** PED-015, CNT-016, FUN-040
- **Риски:** Папки «A1, A2» без связей.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** content review, automated test

### FUN-031 — Доступ к концепту по пререквизитам

- **Формулировка:** Концепт с обязательным пререквизитом недоступен для новых уроков, пока пререквизит не достиг порога `gotowy` (не обязательно полный mastery — см. `ASM-005`). Review и exam-пункты могут ссылаться на более ранние формы.
- **Причина:** Нельзя давать męskoosobowy liczebniki до устойчивого различия rodzaj.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Попытка открыть заблокированный урок показывает недостающий пререквизит.
- **Зависимости:** FUN-030, FUN-080
- **Риски:** Жёсткая блокировка отпугнёт P-VIKTOR, которому нужен точечный ремонт — см. `FUN-035`.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** automated test

### FUN-032 — Спиральные потомки концепта

- **Формулировка:** Система позволяет связать концепты как «тот же столп, глубже» (родитель–потомок), чтобы падеж/аспект не считались закрытыми навсегда.
- **Причина:** PRN-003.
- **Основная персона:** P-DARIA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V3
- **Критерии приёмки:** Mastery потомка не выставляет автоматически mastery всех предков навсегда; спад предка может поставить потомка на review.
- **Зависимости:** PED-015, FUN-082
- **Риски:** Один флаг «cases: done».
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test, content review

### FUN-033 — Рекомендация следующего шага

- **Формулировка:** Система предлагает ровно одну первичную следующую активность: новый концепт, review, слабый навык или exam-модуль, с понятной причиной.
- **Причина:** У P-OLENA нет ресурса выбирать из 40 тем.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Причина рекомендации видима (например: «dopełniacz po 5+ — 3 ошибки за 7 дней»); рекомендация учитывает L1, цель, бюджет времени и очередь SRS.
- **Зависимости:** FUN-011, FUN-012, FUN-090, FUN-141
- **Риски:** Случайный feed.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** manual test, user research

### FUN-034 — Цель смещает, но не вырезает столпы

- **Формулировка:** Цель «работа» или «семья» повышает вес соответствующих тематических текстов и жанров, но не удаляет обязательные грамматические столпы уровня.
- **Причина:** Нельзя выучить «рабочий польский» без аспекта.
- **Основная персона:** P-DARIA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** При любой цели A1-вертикаль всё ещё содержит падежи и орфографию уровня.
- **Зависимости:** FUN-011, PED-001, CNT-019
- **Риски:** Phrasebook «для работы» вместо языка.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** content review

### FUN-035 — Режим ремонта для ложной беглости

- **Формулировка:** Если диагностика показывает высокий рецептивный уровень и низкий формальный, учащийся получает маршрут «ремонт концептов», а не принудительный детский A1 с нуля.
- **Причина:** Работа P-VIKTOR.
- **Основная персона:** P-VIKTOR
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Маршрут состоит из диагностированных слабых концептов + краткой теории + смешанных упражнений; тексты не используют exclusively детский быт, если профиль взрослый.
- **Зависимости:** FUN-020, FUN-013
- **Риски:** Унизительный букварь → отток.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** user research, content review

## 3.5 Уроки и концепты

### FUN-040 — Концепт как учебная сущность

- **Формулировка:** Автор создаёт концепт с: названием, определением границ, уровнем, польской системой-тегом, пререквизитами, целями освоения, связанными упражнениями.
- **Причина:** PRN-002.
- **Основная персона:** P-AUTHOR
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Без границ («что считается освоением / что ещё не входит») концепт нельзя отправить в review.
- **Зависимости:** CNT-002, PED-021
- **Риски:** Тема «грамматика A1» как один концепт.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test, content review

### FUN-041 — Урок собирает концепты

- **Формулировка:** Урок ссылается на 1–5 концептов, содержит теорию, примеры, контрпримеры и набор упражнений. Завершение урока пишется отдельно от mastery.
- **Причина:** Иначе урок снова станет единицей лживого прогресса.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** API/экран прогресса различает `lesson_completed` и `concept_mastered`; урок без упражнений не публикуется.
- **Зависимости:** FUN-080, CNT-018
- **Риски:** Видео-лекция без практики.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test

### FUN-042 — Предпросмотр урока как учащийся

- **Формулировка:** Автор и reviewer открывают урок в режиме учащегося без публикации и без записи в живую статистику учащихся.
- **Причина:** Иначе ошибки ключей всплывают на P-OLENA.
- **Основная персона:** P-AUTHOR
- **Приоритет:** Advanced
- **Target necessity:** Important
- **Delivery stage:** V0
- **Критерии приёмки:** Preview не изменяет mastery реальных учащихся; ключи видны reviewer.
- **Зависимости:** FUN-170
- **Риски:** Preview пишет в прод-аналитику.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** automated test

## 3.6 Теория, примеры, контрпримеры

### FUN-050 — Теоретический материал концепта

- **Формулировка:** У концепта есть теоретический блок: правило, условия применения, связь с коммуникативной функцией, ссылка на уровень. Блок доступен на UI-языке учащегося; примеры на польском.
- **Причина:** Восточнославянский учащийся часто «уже знает термин», но не знает польской границы.
- **Основная персона:** P-DARIA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Теория не публикуется без ≥1 польского примера; метаязык не подменяет объектный польский.
- **Зависимости:** I18N-003, PED-016, CNT-018
- **Риски:** Длинная лекция без примера.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** linguistic review, content review

### FUN-051 — Примеры и контрпримеры

- **Формулировка:** Система хранит примеры и контрпримеры как отдельные единицы: польский текст, глосса/перевод на L1, пометка «корректно / некорректно», объяснение границы.
- **Причина:** Контрпример — способ показать, почему калька *w sklep* невозможна.
- **Основная персона:** P-VIKTOR
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Некорректный пример визуально не спутать с корректным; у контрпримера есть исправление.
- **Зависимости:** PRN-005, PED-017
- **Риски:** Красный крест без правильной формы.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** manual test, linguistic review

### FUN-052 — L1-заметка

- **Формулировка:** К концепту можно привязать отдельные заметки для UKR, RUS, BEL: контраст, ложный друг, типичная калька, чего не переносить.
- **Причина:** USR-002.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Учащийся с L1=UKR не видит RUS-заметку как основную, если обе существуют; отсутствие заметки для L1 видимо автору как пробел покрытия.
- **Зависимости:** PED-014, CNT-012
- **Риски:** Автоперевод русской заметки.
- **Статус:** Proposed

## 3.7 Упражнения, подсказки, ошибки

### FUN-060 — Движок упражнений

- **Формулировка:** Система исполняет типы заданий из каталога `CNT-017`, показывает стимул, принимает ответ, сравнивает с ключом для закрытых типов и пишет результат в свидетельства mastery.
- **Причина:** Без единого исполнения типы разъедутся по «страничкам».
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Каждый опубликованный закрытый пункт имеет ключ и код концепта; ответ сохраняется с timestamp.
- **Зависимости:** CNT-013, CNT-017, ASM-008
- **Риски:** Фронтенд-only проверка, которую можно подменить.
- **Статус:** Proposed
- **Источник:** Бриф. Ограничение для архитектуры: проверка ключа не может жить только на клиенте.
- **Проверка:** automated test

### FUN-061 — Банк вариантов, не один и тот же пункт

- **Формулировка:** Повтор концепта берёт другой пункт из банка, если банк ≥3; один и тот же item id не показывается в одной сессии повторно, пока есть неиспользованные.
- **Причина:** Запоминание ключа ≠ освоение *dopełniacz*.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** При банке из 5 пунктов 3 попытки подряд дают 3 разных item id.
- **Зависимости:** CNT-013
- **Риски:** Банк из одного предложения.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** automated test

### FUN-062 — Немедленная обратная связь на закрытых пунктах

- **Формулировка:** После ответа на закрытый пункт учащийся сразу видит верно/неверно, правильную форму и привязку к концепту.
- **Причина:** Отложенная галочка не чинит падеж в той же минуте.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** В учебном режиме (не exam-mode) обратная связь ≤1 действие после ответа.
- **Зависимости:** FUN-160, ASM-015
- **Риски:** Exam-mode случайно показывает ключ.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test, manual test

### FUN-063 — Подсказка без выдачи ключа сразу

- **Формулировка:** Учащийся может запросить до 2 уровней подсказки: (1) направление правила, (2) сужение выбора. Полный ключ — только после ответа или отказа.
- **Причина:** Польская форма часто угадывается по окончанию, если показать его в подсказке.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Использование подсказки помечает свидетельство как `hinted` и не может одно засчитать полный mastery-балл.
- **Зависимости:** FUN-080, ASM-005
- **Риски:** Подсказка = ответ.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION` о двух уровнях
- **Проверка:** automated test

### FUN-064 — Объяснение ошибки по коду

- **Формулировка:** Автор привязывает к ключу ожидаемые неверные ответы (дистракторы) с кодом явления: например `genitive-after-negation`, `aspect-process-vs-result`, `mo-agreement`, `orth-rz-vs-z`. Система показывает утверждённое объяснение этого кода.
- **Причина:** USR-007.
- **Основная персона:** P-VIKTOR
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Для дистрактора из банка показывается банкское объяснение, а не свободная генерация; неизвестный ответ — общее «неверная форма» + правильный ключ + концепт.
- **Зависимости:** PED-013, BUS-010, FUN-066
- **Риски:** Свободный LLM-разбор.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** linguistic review, automated test

### FUN-065 — L1-контраст в объяснении

- **Формулировка:** Если у кода ошибки есть L1-контраст для языка учащегося, он показывается («в украинском так можно, в польском после *nie lubić* нужен dopełniacz»).
- **Причина:** Иначе объяснение остаётся абстрактным.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Контраст исчезает при смене L1 на язык без этой карточки.
- **Зависимости:** FUN-052, FUN-064
- **Риски:** Неверный контраст (приписать украинскому русское правило).
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** linguistic review

### FUN-066 — Базовый путь без зависимости от генеративной модели

- **Формулировка:** Базовый учебный путь не требует генеративной модели для объяснения ошибки. Если AI-перефраз когда-либо включат, он может только пересказывать утверждённый банк, явно помечен как формирующий/неофициальный и обязан быть полностью отключаемым без поломки обучения. Механизм отключения — архитектура.
- **Причина:** BUS-006, BUS-010.
- **Основная персона:** P-ADMIN
- **Приоритет:** Critical
- **Target necessity:** Mandatory
- **Delivery stage:** V0
- **Критерии приёмки:** При отключённых AI-функциях все объяснения берутся из утверждённого банка; нет обязательного сетевого вызова модели на закрытом пункте.
- **Зависимости:** NFR-004, PRN-010
- **Риски:** Тихий fallback на модель.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** manual test, automated test

## 3.8 Модель mastery

### FUN-080 — Состояние освоения концепта

- **Формулировка:** У каждого учащегося каждый концепт имеет объяснимое состояние освоения (как минимум: не начат / в работе / готов к использованию / освоен / требует повторения — названия и точный enum выбирает архитектура). Состояние выводится из свидетельств, не из клика «далее».
- **Причина:** BUS-003.
- **Основная персона:** P-DARIA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Завершение урока не ставит «освоен». Переход в «освоен» требует свидетельств по правилам `ASM-005`.
- **Зависимости:** ASM-005, PRN-002
- **Риски:** Бинарный checkbox урока.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` (пороги — `ASSUMPTION` в ASM-005)
- **Проверка:** automated test

### FUN-081 — Свидетельство

- **Формулировка:** Каждая оценённая попытка создаёт свидетельство: концепт, тип задания, навык, hinted/exam, результат, время.
- **Причина:** Mastery должна аудироваться.
- **Основная персона:** P-ADMIN
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V1
- **Критерии приёмки:** Можно выбрать концепт и увидеть ленту свидетельств учащегося (сам учащийся — свою).
- **Зависимости:** FUN-060, SEC-004
- **Риски:** Агрегат без сырых событий.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** automated test

### FUN-082 — Спад и возврат в очередь

- **Формулировка:** Концепт без свежих свидетельств переходит в `decaying` и попадает в SRS. Ошибка в ранее mastered концепте снижает состояние минимум до `gotowy` или `learning` по правилам ASM-005.
- **Причина:** Польская морфология без возврата рассыпается.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Есть дата, после которой `mastered` становится `decaying`, если нет нового свидетельства.
- **Зависимости:** FUN-090, ASM-005
- **Риски:** Вечный зелёный статус.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION` о сроке спада
- **Проверка:** automated test

### FUN-083 — Mastery не ставится только на рецептивных пунктах, если цель концепта продуктивная

- **Формулировка:** Если у концепта цель `productive`, состояние `mastered` требует хотя бы одного продуктивного или «примени в предложении» свидетельства, не только multiple choice.
- **Причина:** Узнать *w sklepie* в тесте ≠ сказать это в urzędzie.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Концепт с флагом `productive` остаётся `gotowy`, пока нет qualifying productive evidence.
- **Зависимости:** ASM-005, USR-010, DEC-002
- **Риски:** Весь B1 на галочках.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test

## 3.9 Интервальное повторение и чередование

### FUN-090 — Очередь интервального повторения

- **Формулировка:** Система ведёт очередь review по концептам и лексическим рамкам (слово + управление / видовая пара), а не только по изолированным леммам.

- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Элемент очереди несёт концепт или «лемма+rekcja+aspect»; изолированное слово без рамки не является единственным типом review.
- **Зависимости:** PED-002, FUN-103
- **Риски:** Anki-клон без польской рамки.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** content review, automated test

### FUN-091 — Чередование навыков

- **Формулировка:** Планировщик недели не назначает все сессии одному навыку, если у учащегося опубликованы материалы ≥3 навыков его уровня.
- **Причина:** Экзамен и жизнь не про одну грамматику.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** В 7-дневном плане при 5+ сессиях есть ≥3 навыка.
- **Зависимости:** PED-018, FUN-033
- **Риски:** Неделя gap-fill.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** automated test

### FUN-092 — Приоритет ошибочных явлений

- **Формулировка:** Коды ошибок последних 14 дней повышают приоритет связанных концептов в очереди.
- **Причина:** P-VIKTOR делает одну и ту же кальку.
- **Основная персона:** P-VIKTOR
- **Приоритет:** Advanced
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Концепт с ≥3 ошибками за 14 дней появляется в рекомендации раньше нового необязательного концепта того же уровня.
- **Зависимости:** FUN-064, FUN-033
- **Риски:** Новизна ради новизны.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION` порога 3/14
- **Проверка:** automated test

## 3.10 Словарь и морфологический разбор

### FUN-100 — Учебный словарь продукта

- **Формулировка:** Система предоставляет словарь единиц, допущенных в контент: лемма, L1-эквиваленты для UKR/RUS/BEL, уровень, тема, пометы.
- **Причина:** Внешний произвольный словарь принесёт неконтролируемые формы и чужой copyright.
- **Основная персона:** P-DARIA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Слово, встречающееся в опубликованном уроке целевого минимума, либо есть в словаре, либо помечено как *вне минимума* с разбором.
- **Зависимости:** CNT-016, I18N-002
- **Риски:** Скрапинг чужого словника.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** content review

### FUN-101 — Разбор словоформы

- **Формулировка:** Учащийся вводит или выделяет форму и получает разбор: лемма, часть речи, падеж/лицо/время/аспект где применимо, род, число, męskoosobowość.
- **Причина:** USR-011.
- **Основная персона:** P-DARIA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Для форм из словаря разбор однозначен или предлагает ранжированные разборы омонимии (*jest* vs *jeść* не путать без контекста — тогда пометка «нужен контекст»).
- **Зависимости:** FUN-100
- **Риски:** Один «умный» морфоанализатор без ключа как источник истины — допустим только как помощник автора, не как скрытый учитель без review. Ограничение: авторазбор, показанный учащемуся, покрывается словарём продукта или помечен как неуверенный.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** linguistic review, manual test

### FUN-102 — Парадигма

- **Формулировка:** Для существительных, прилагательных, местоимений, числительных и глаголов словаря доступна полная учебная парадигма нужного уровня, не обязательно академически исчерпывающая.
- **Причина:** Польский учат формами, не леммами.
- **Основная персона:** P-VIKTOR
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Парадигма показывает все семь падежей тамо, где у леммы есть падеж; для глагола — вид, время, лицо; исключения помечены.
- **Зависимости:** PED-001, PED-004
- **Риски:** Урезанная таблица «главные формы» без wołacz.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** linguistic review

### FUN-103 — Управление и видовая пара

- **Формулировка:** Словарная статья глагола/предлога показывает rekcja (падеж и предлог) и видовую пару, если пара входит в контент.
- **Причина:** *dziękować komu, czekać na kogo/co, słuchać czego* — это польский, а не «слово + перевод».
- **Основная персона:** P-OLENA

- **Зависимости:** PED-002, PED-004, PED-012
- **Риски:** Перевод *słuchać = listen* без dopełniacz.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** linguistic review, content review

## 3.11 Аудио и произношение

### FUN-110 — Аудио к учебным единицам

- **Формулировка:** Задания аудирования и словарные единицы с пометкой `audio-required` имеют запись речи человека (или иначе лицензированный источник, прошедший review). Оцениваемый listening не опирается на необработанный произвольный TTS как единственный стимул.
- **Причина:** Польские стечения согласных, оглушение и предпоследнее ударение должны звучать как польский, не как синтетический компромисс.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Mandatory
- **Delivery stage:** V2
- **Критерии приёмки:** Listening-пункт без валидного аудио не публикуется; метаданные содержат спикера, дату, права.
- **Зависимости:** CNT-014, PED-009, DEC-014
- **Риски:** TTS, который ставит ударение на последний слог.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` (`ASSUMPTION` о человеческом аудио для оценки)
- **Проверка:** content review, linguistic review

### FUN-111 — Показ ударения и сложных мест

- **Формулировка:** В фонетических концептах учащийся видит место ударения и пометки исключений (*matematyka, uniwersytet, w ogóle*), а также типичные стечения.
- **Причина:** Восточнославянское подвижное ударение даёт системные ошибки.
- **Основная персона:** P-NATALLIA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Фонетический концепт без разметки ударения не публикуется.
- **Зависимости:** PED-009
- **Риски:** Только орфография без звука.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** linguistic review

### FUN-112 — Произносительные упражнения

- **Формулировка:** Есть типы: минимальные пары, повтор за образцом, стечения, оглушение. Сравнение с образцом не является единственным основанием mastery, если используется автоматический score.
- **Причина:** Автооценка произношения ненадёжна; фонетика всё равно нужна.
- **Основная персона:** P-OLENA
- **Приоритет:** Advanced
- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Автоscore, если есть, помечен как ориентир; mastery фонетического концепта может опираться на закрытые perceptive задания (выбор пары, ударение) без авто-ASR.
- **Зависимости:** PED-023, DEC-015
- **Риски:** «85% native» от чёрного ящика.
- **Статус:** Proposed
- **Источник:** `PRODUCT ANALYSIS` / `REQUIRES USER VALIDATION`
- **Проверка:** manual test, linguistic review

## 3.19 Подписка и entitlements

### FUN-200 — Управление доступом к функциям (коммерческая граница)

- **Формулировка:** Система различает бесплатный и платный доступ к функциям/вертикалям. Конкретная реализация (entitlements, feature flags, подписка) — архитектура. **Рабочее предположение (не утверждённая монетизация):** placement и регистрация бесплатны; полная траектория и exam-mode могут быть платными (`DEC-001`).
- **Причина:** Без границы доступа нельзя ни открыть всё бесплатно устойчиво, ни закрыть диагностику.
- **Основная персона:** P-ADMIN
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Закрытый объект даёт понятную причину отказа; placement не требует оплаты (пока действует рабочее предположение).
- **Зависимости:** DEC-001, BUS-006
- **Риски:** Paywall на диагностике.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION` (DEC-001)
- **Проверка:** automated test, manual test

### FUN-201 — Состояние подписки видно учащемуся

- **Формулировка:** Учащийся видит, что включено, до какой даты, и что будет закрыто.
- **Причина:** Доверие и отказ от тёмных паттернов.
- **Основная персона:** P-OLENA
- **Приоритет:** Core
- **Target necessity:** Important
- **Delivery stage:** V1
- **Критерии приёмки:** Дата окончания и список закрытых вертикалей отображаются до попытки входа в закрытый урок.
- **Зависимости:** FUN-200
- **Риски:** Списание без ясного состава.
- **Статус:** Proposed
- **Источник:** `ASSUMPTION`
- **Проверка:** manual test

### FUN-202 — Потеря entitlement не уничтожает данные

- **Формулировка:** Истечение оплаты скрывает защищённый контент, но сохраняет профиль, свидетельства и позволяет экспорт.

### FUN-181 — Педагогические метрики, не vanity как главные

- **Target necessity:** Important
- **Delivery stage:** V2
- **Критерии приёмки:** Первый экран аналитики не содержит DAU/streak как главные числа; содержит ≥4 педагогические метрики из списка выше.
- **Зависимости:** PRN-011, BUS-003
- **Риски:** Оптимизация привыкания вместо освоения.

### FUN-182 — Запрет продажи учебных текстов третьим лицам для обучения моделей

## 3.23 Ограничения, влияющие на будущую архитектуру

Эти пункты — требования-ограничения, не проект:

1. Проверка ключей закрытых заданий не может быть только клиентской (`FUN-060`).
2. Базовый учебный путь работает без генеративной модели (`FUN-066`, `NFR-004`).
3. Голос не пишется скрыто (`FUN-130`).
4. Версии контента неизменяемы после публикации (`FUN-172`).
5. Self-approve запрещён (`FUN-003`, `FUN-175`).
6. Аналитика должна уметь резать по концепту, L1 и модулю экзамена (`FUN-180`).
